# АПД Строй — накопленные знания проекта (для быстрого подключения на новой машине)

Этот файл — куратский снимок того, что узнал и чему научился Claude Code за
время работы над автоматизацией маркетинга АПД Строй (каркасное домостроение,
Пермь). Он пересобирается вручную время от времени, не автоматически — если
что-то здесь выглядит устаревшим, проверяйте текущее состояние кода/БД, а не
верьте этому файлу вслепую.

## Компания и обязательные факты в контенте

- Срок строительства — 45 дней, **всегда** с оговоркой «по типовым проектам».
- Первоначальный взнос по семейной ипотеке — от 100 000 ₽.
- Контроль работ на всех этапах строительства.
- «Под ключ» — не только стройка, но и помощь с оформлением ипотеки и подбором участка.
- Честная цена уже включает отделку под ключ (в отличие от рынка, где часто продают
  «коробку» без отделки).
- Сквозной слоган: «Заезжай и живи!» (совпадает с hero-секцией сайта).
- Юмор — самоирония про скорость/лёгкость стройки по сравнению с обычными ожиданиями,
  не рандомные шутки не по теме.
- Реальные названия типовых проектов — «Практик-75», «Практик-90» (не «Дом-75/90»).

## Юридические ограничения (Instagram, 72-ФЗ)

С 01.09.2025 реклама Meta-продуктов (Instagram) в РФ запрещена в любом виде —
включая призывы подписаться/перейти по ссылке/написать в бота. Штраф юрлицу
200 000–500 000 ₽ за каждый факт.

**Правило по умолчанию:** пассивный CTA без глагола действия — «Следите за
проектом — продолжение в сторис.» Это должно использоваться, когда Claude сам
формулирует CTA.

**Исключение:** если пользователь явно продиктовал текст CTA в самом промпте
сценария — использовать его дословно (после однократного предупреждения о
риске, которое не нужно повторять при каждом следующем ролике).

## Аватар: робот отменён, Nicholas — единственный аватар

Решение от 30.07.2026, окончательное: робот-аватар (гусеницы, гранёная голова,
соломенная шляпа) больше не используется вообще. Причина — MuseTalk
детерминированно обрезает ролик короче исходного, а `fal-ai/hunyuan-avatar`
визуально переосмысливает голову робота в морду тюленя/собаки, плюс жёсткий
лимит длины ~5.2с. Оба непригодны для стилизованного не-фотореалистичного лица.

Теперь оба трека используют человека-аватара **Nicholas** (группа аватаров
HeyGen `309bab597036410b9a40319905af3ce3`). Пайплайн: Yandex TTS (voice=anton,
speed=1.1) → fal.ai MuseTalk (видео+аудио → липсинк) → апскейл при
необходимости. Подтверждено надёжным на фотореалистичном лице (в отличие от
робота).

**Библиотека силуэтов Nicholas, готовых для MuseTalk без затрат HeyGen-кредитов:**
- `content/udachnaya-01-45-dney/assets/clip1.mp4` — зима, чёрная куртка, лес.
- `content/udachnaya-01-yandex-test/assets/clip1.mp4` — зима, вариант.
- `content/udachnaya-02-vznos-100k/assets/clip1.mp4` — зима, изба.
- `content/udachnaya-03-cena-permi/assets/clip1.mp4` — крыша/город, лето, серый
  пиджак — **исходно белые полосы сверху/снизу**, чинится кроп-фиксом ниже, 16.36с.
- `content/udachnaya-04-gibkost-uchastok/assets/clip1.mp4` — офис, тёмно-синий
  пиджак, чистый без белых полос, 17.96с.
- `content/udachnaya-05-mify/assets/clip1.mp4`, `udachnaya-06-dom-75/assets/clip1.mp4` — зима.

Летнего/офисного фона в библиотеке больше нет вариантов — только эти два
"чистых" (не-зимних). Третий фон возможен только новой генерацией через
HeyGen (см. блокер по кредитам ниже).

**Кроп-фикс для рооftop-клипа** (белые полосы, видимый контент только
y=656–1263 из 1920px): `ffmpeg -vf "crop=1080:607:0:656,scale=-2:1920,crop=1080:1920"`
— кроп видимой полосы → апскейл с сохранением пропорций → кроп по центру до
1080 ширины. НЕ растягивать без сохранения пропорций (`scale=1080:1920`
напрямую) — даёт видимое искажение лица.

## Строгие правила композиции роликов ветки ИНФОРМАЦИОННЫЕ

1. **Один непрерывный кадр** — нельзя менять аватара/локацию в кадре внутри
   одного ролика. Один `<video>`+`<audio>` на всю длительность, без
   кроссфейда/переключения между клипами.
2. **Чередование фонов ОБЯЗАТЕЛЬНО, без исключений.** Если сценарий не влезает
   в фон, который должен идти по очереди (например «крыша», лимит 16.36с) —
   обрезать текст сильнее, а не переключаться на «удобный» фон. Нарушение
   этого правила уже приводило к отклонению готового ролика пользователем
   (30.07.2026, reel-15). Если после разумной обрезки текст всё равно не
   влезает ни в один фон — остановиться и спросить пользователя.
3. **≤20 секунд** на ролик — жёсткий потолок, независимо от лимита конкретного фона.
4. **Хештеги** — каждый caption для ветки ИНФОРМАЦИОННЫЕ должен включать
   `#стройка #дом #дача` в дополнение к теме-специфичным тегам (например
   `#каркасныйдом #пермь #апдстрой`).
5. **Проверка сценария на соответствие правилам — ДО генерации видео**, не после.

## Технические паттерны TTS/рендера

- Yandex TTS v3 (`utteranceSynthesis`) имеет недокументированный лимит длины
  текста на один запрос (~200–330 символов небезопасно). Рабочий паттерн:
  разбивать сценарий на 2–4 части ≤~150–200 символов, синтезировать каждую
  отдельно, склеивать WAV через `ffmpeg -f concat -safe 0`.
- Тайминг субтитров — пропорционально длине фразы в символах относительно
  окна речи (`длительность_клипа - 0.3с лид - 0.2с хвост`).
- HyperFrames-композиция: `data-start`/`data-duration` управляют видимостью
  клипов автоматически — не анимировать `opacity` видео вручную (лишний ручной
  кроссфейд вызывает lint-ошибку `gsap_exit_missing_hard_kill`).
- Рендер: `HYPERFRAMES_FFMPEG_PATH`/`HYPERFRAMES_FFPROBE_PATH` указывают на
  `C:\ffmpeg-bin\` на текущей машине.

## Дисциплина работы с БД и подтверждениями

**Никогда не доверять устному «одобрено» без проверки БД.** Несколько раз
пользователь считал ролик одобренным (через Telegram-кнопку/текст), но
`content_pipeline.stage` фактически оставался `awaiting_review` — подтверждение
через Telegram имеет повторяющийся, не до конца объяснённый паттерн сбоя.
Перед тем как считать ролик решённым и переходить к следующему — всегда
проверять реальный `stage` в БД.

Идемпотентная ручная схема одобрения+постановки в очередь (когда пользователь
говорит «одобри сам» или Telegram-подтверждение не сработало): `getPipelineRow`
→ `getActiveScheduleForReel` (проверка, что уже не поставлено в очередь) →
`getNextDailySlot` → `enqueuePost` → `upsertStage(..., 'approved', {platform:'instagram'})`.

## Ежедневный отчёт и бэкап (`server.js` `/cron/daily-report`)

- Отчёт по заявкам (`sendDailyReport`) отправляется **каждый день** через
  GitHub Actions cron (`.github/workflows/daily-report.yml`).
- Бэкап-документ (`sendBackupToTelegram`, `lib/backup.js`) отправляется **раз
  в 3 дня** (изменено с ежедневной отправки по решению пользователя
  30.07.2026) — логика в `isBackupDueToday()` в `server.js`, привязана к дню
  года по модулю 3, без хранения состояния между запусками.
- Раньше ошибки отправки бэкапа тихо проглатывались (`console.error`, не
  попадали в HTTP-ответ) — из-за этого нельзя было отличить «бэкап не пришёл
  из-за бага» от «бэкап просто никто не заметил». Исправлено: результат
  отправки бэкапа (`{sent: true/false, error?}`) теперь включён в JSON-ответ
  `/cron/daily-report`.
- `lib/backup.js` собирает все инфраструктурные секреты (GitHub, Timeweb,
  Render, Google Sheets, Telegram, CRON_SECRET) + инструкцию восстановления с
  нуля + содержимое `claude-global-instructions.md` + этот файл
  (`claude-project-knowledge.md`) — оба читаются из репозитория бота, поэтому
  доступны на любом хостинге, где задеплоен код (в отличие от `~/.claude/`
  файлов, которые существуют только на локальной машине пользователя).
